4명, 4주, AWS 제외. 작업량은 기능별 가중치로 추정한 값이며(합계 약 95점, 1인당 약 24점) 정확한 수치가 아니라 균형 확인용이다.

## 3. 담당별 구현 내용

### A. 결제 코어 — 결제 및 동시성 제어
- **멱등키 처리**: 요청별 멱등키 검증, 중복 요청 방지, 같은 요청 재전송 시 기존 결과 반환, 같은 키에 다른 내용이면 거절
- **결제**: QR과 가맹점 검증, 지갑 차감(`WalletService.debit`), 캐시백 예산 예약(`CashbackService.reserve`), QR 사용 처리(`QrService.markUsed`), 결제 내역 저장. 월 한도 차감과 예산 확보까지 한 트랜잭션
- **결제 결과 재조회**: **멱등키 기반**(`GET /api/payments/by-key/{idempotencyKey}`). 결과를 모르는 상황에서는 결제 ID를 받지 못하므로 멱등키로 조회
- **결제 취소**: 취소 가능 여부 확인, 지갑 환급(`WalletService.credit`), 캐시백 적립 취소 및 예산 복원, 중복 취소 방지
- **사장님 결제 내역**: 가맹점별, 기간별 결제와 취소 내역. 일 정산과 같은 집계 기준(취소는 취소한 날 반영)
- **테스트**: 같은 멱등키 중복 요청, 같은 지갑의 동시 결제, 같은 예산에 대한 동시 예약, 실패 시 롤백

### B. 캐시백·예산·정책
- **정책 관리**: 요율과 기간 등록, 기간 겹침 금지, 결제 시점 적용 정책 결정, 변경 이력
- **적립 계산과 적립**: 데브머니 사용분 × 접수 시각 요율, 소수점 유지, 월 한도 차감, 적립 건 저장, 결제 취소 시 적립 취소
- **적립 지급 배치**: 결제 다음날 00:00 + 3일, 매시간 실행, 건별 트랜잭션, 대기에서 지급 완료로 조건부 갱신, 음수 캐시백 상계
- **연/월 예산 관리**: 연 예산, 월 예산 배정, 집행액과 잔여, 예약·차감·복원, 소진 시 적립 중단(결제는 진행)
- **예산 이월**: 월말 잔여 계산, 다음 달 이월, 이월 이력(`cashback_budget_transfer`), 연 총예산 초과 방지
- **예산 공지 후 중단/긴급 중단**: 대비금 기준(최근 7일 일평균 × 5일), 소모 시작 시 3일 후 중단 공지, 대비금 10% 남으면 긴급 중단
- **운영자 조회**: 월 예산 현황(월별 배정, 이월 유입, 집행, 예정, 잔여), 적립 내역 전체 조회(상태, 기간, 이용자 필터)
- **주요 테이블**: `cashback_annual_budget`, `cashback_monthly_budget`, `cashback_budget_transfer`, `cashback_policy`, `cashback_earning`

### C. 회원·지갑
- **회원**: 가입(모의계좌 1개와 지갑 생성, 초기 잔액 100만원), 로그인, 내 정보, 탈퇴 정산
- **인증**: JWT, 권한(USER / OWNER / ADMIN), 간편 비밀번호 6자리 검증, 5회 실패 시 잠금, 잠금 해제
- **지갑**: 조회(데브머니, 캐시백, 적립 예정 분리 표시), 충전, 환불(데브머니만), 거래 내역
- **이용자 캐시백 조회**: 월 한도 조회, 적립 내역 조회(`CashbackQueryService` 사용)
- **탈퇴 정산**: 음수 캐시백을 데브머니로 정산, 부족하면 계좌에서 충전, 남은 데브머니 환불. B와 합동 구현

### D. 가맹점·QR·정산
- **가맹점**: 등록과 고정 QR 발급, 수정, 상태 관리, 이름 검색과 주변 검색(가맹점 찾기)
- **QR**: 동적 QR 생성(3분 만료), 스캔 조회(요율, 남은 한도 포함), 상태 조회(폴링), 고정 QR 결제, 중복 사용 방지
- **일 정산**: 매일 00:10, 순매출(결제 - 취소) + 전일 이월, 음수면 0원 정산 후 이월, 가맹점·날짜별 중복 생성 방지
- **원장 대사**: 매일 00:30, 7종 독립 실행, 읽기만 하고 고치지 않음, 결과는 `reconciliation_result`에 저장

## 6. 담당 간 연동 (인터페이스를 가장 먼저 확정)

| 연동 | 내용 |
|---|---|
| A ← C | 지갑 차감, 환급 (`WalletService.debit / credit`) |
| A ← B | 캐시백 예산 예약, 취소 (`CashbackService.reserve / cancel`) |
| A ← D | QR 사용 처리 (`QrService.markUsed`) |
| B → C | 캐시백 지급 시 지갑 적립 |
| C ← B | 월 한도, 적립 내역 조회 (`CashbackQueryService`). 계산과 상태 판단은 B, C는 응답 조립만 |
| D ← B | QR 스캔 조회에 필요한 요율, 남은 한도 |

A와 B, A와 C의 연동은 가장 먼저 확정한다. B가 끝나기 전에는 A가 적립 0원 스텁으로 결제를 먼저 완성한다.

## 7. 협업 규칙
- 스키마 변경은 PR로만 한다. 전체 DDL은 B가 1주차 첫날 확정한다.
